# Cifrado de archivos y registros en streaming

El panel admite AES-256-GCM, AES-256-CTR, AES-256-CBC y ChaCha20-Poly1305. El modo de archivo completo procesa bytes arbitrarios en streaming. GCM y ChaCha20-Poly1305 usan un archivo separado con la etiqueta de 16 bytes; el descifrado deja la salida en preparación hasta que la autenticación termina correctamente. CTR y CBC no autentican el texto cifrado.

El modo por líneas trata cada línea de texto como un registro independiente y aplica el charset y la codificación Base64URL o Hexadecimal elegidos. Los registros AEAD llevan nonce y etiqueta propios. Los registros CBC usan el IV indicado y no tienen autenticación; los registros CBC compactos, sin cabecera, requieren la misma opción compacta al leerlos. Conserva la clave y los valores aplicables de nonce/IV, AAD, etiqueta, charset y codificación para descifrar.

La selección de origen/destino, etiqueta, generación de nonce y recetas son acciones independientes. El generador crea valores de 12 bytes para GCM y ChaCha20-Poly1305 y de 16 bytes para CTR y CBC. Esos valores generados no equivalen a la validación: el modo de archivo completo exige al menos 12 bytes y el proveedor aplica además las comprobaciones del modo; AEAD por líneas crea un nonce nuevo para cada registro, mientras que CBC por líneas usa el IV indicado. El selector de charset para líneas ofrece UTF-8 y las páginas IBM EBCDIC listadas desde IBM037 hasta IBM1149. Las recetas conservan el perfil y parámetros públicos, pero nunca incluyen la clave secreta. Cancelar la selección de archivo o la confirmación de sobrescritura no inicia la operación. Abrir la ayuda contextual no inspecciona ni modifica archivos.
